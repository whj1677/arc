# ARC · 工程全貌与功能走读

ARC 帮助你沿着真实源码连续理解一个工程：查看工程全貌、选择功能、点选步骤或文件、原位提问、查看依据并继续追问。Agent 负责分析，ARC 负责冻结上下文、校验来源、展示和保存阅读成果。

## 正式工作台与调用链

在仓库根目录运行 `npm start`，即进入新的 Electron 正式工作台。Kimi `k3.1-pro` 负责界面方案与前端组件，GPT 6 Astra 负责调用数据和工程记录，Codex 负责集成、审阅修正及验收。全部入口连接原有真实工程、存储和执行通道。

左侧“调用链”直接打开当前说明中的函数图；没有函数分析时会引导选择功能并在 ARC 内分析。选择真实入口后，同文件函数归在同一文件区域，跨文件连线标出目标文件。点击函数或关系，在右侧查看参数、返回、条件、调用点与定义；点击来源可打开冻结快照中的准确行号。上方保留入口至当前函数的一条代表最短路径，可展开上下游继续跳转。它不代表唯一调用路径或实际运行轨迹；未知实现保留边界，不猜测后续调用。

“函数调用链 / 调用时间图”可以切换，入口、图类型和选中对象随阅读位置保存。右侧“提问”沿用当前对象、结果、源码快照及相关批注；发送即通过官方 Codex 执行，答案回到原问题。执行期间切换对象不会改变归属，可回来继续追问。选择外部 MCP 时明确显示等待领取，不冒充正在执行。系统协作、业务流程、协作关系、组成思维导图、内部模块、文件、依赖、历史比较和原有阅读数据继续保留；上方目录按钮可展开其他视图。

2026-11-14 正式 Electron 实测使用当前仓库的 `src/main` 真实工程目录，新建场景并通过官方 Codex 生成 `ArcService.source → readSource → safeFile → relativePath` 调用路径，未导入手写结果：8 个函数、8 条调用边、22 处源码引用均经独立源码核对。完整详细分析沿用本机 `gpt-6-astra / ultra` 配置，用时 **782.249 秒**，不能称为快速首轮或普通首次概况耗时。真实原位纠错与续问分别 **49.876 秒、62.035 秒**；公开任务输入包含纠错批注和前答，切换函数后回答仍归原问题，重启后恢复两条问答、批注和阅读位置。分析期间本工程其他文件发生变化，界面保留“来源待核对”，问答继续使用原冻结快照，未冒充最新代码。

本轮类型检查、构建、全部 193 项单元/集成测试通过；最终局部修复另复验相关 23 项，调用关系选择修复复验 11 项。模拟测试用于验证状态、版本冲突和边界，不计真实 Agent 验收。正式界面已实际检查工程方案新增、编辑、版本历史及重启恢复，方案转任务自动带入栏目线索；调用链、时间图、源码点击和 960 像素窄窗口可操作。栏目草稿与选择位置的工程导出恢复经集成测试通过，其他工程数据不混入。

## 工程上下文与开发记录

打开工程后，“工程全貌”先显示有来源的用途、模块、接口候选、规则及构建入口，再沿用原有 Codex 分析展示架构与功能。配置事实、文档声明、用户补充和来源冲突分开标识；点“来源与补充”可读冻结文件并纠正。人和 Agent 通过同一个服务读取这些内容，长文、来源和已有分析按需展开，重新扫描保留用户补充。

在“工程与开发”查看五个栏目：**方案、架构、设计、任务、验证**。已识别的对应工程文档按实际来源进入栏目；缺失内容明确显示待补充，不自动编造整套方案。可以补充或编辑记录、查看版本与冻结来源；用户和 Agent 使用同一份上下文。架构栏目可返回真实工程架构图。“转为开发任务”会带入当前栏目线索，补充具体目标后再执行。验证计划与实际命令验证结果分开显示，计划不等于通过。

在“任务”输入目标并点“开始开发”（也可 Ctrl+Enter）。开发通道在真实工作区执行，沿用官方 Codex 的模型和认证，使用工作区写入权限与原审批机制；原位追问仍使用只读冻结源码。任务固定工程、开始基线和已有改动，结果自动保存文件差异、验证、决定和待处理项。Agent 可按需回填方案、架构、设计和验证计划，也可通过 `arc_save_engineering_entry` 更新；所有 Agent 归纳保持待复核，小改动不要求填齐栏目。栏目版本冲突单独记录，不丢失已经完成的开发与验证。切换工程不改变归属；“继续此任务”追加尝试和版本。取消不会回滚已有代码，重启不会自动重放未完成的写操作。

“接入与恢复 → 连接 Agent / 迁移旧规则”用于可选的外部会话：安装受管理的工程规则并注册 ARC MCP。此后在该工作区开启普通 Codex 新会话，直接描述开发请求；规则会引导其读取 `arc_engineering_context`、开始/续接任务并结束回填，无需每次提醒调用工具。仅打开 ARC 内开发不要求先连接外部 Agent。MCP 本身不唤醒已打开对话，也不能停止外部 Agent；连接中断时已有任务的回填保存在本机待同步队列，重开 ARC 自动重试，也可在菜单检查/重试。授权按实际工作区保留，界面切换不改变已授权任务的归属。

验证状态与任务状态分开。通过状态绑定实际命令、退出码、日志和对应代码状态；外部 Agent 的报告标为自报。代码身份包含普通工作区文件的内容哈希，阅读快照之外的二进制、非 UTF-8 和超过 2 MiB 的文件也纳入记录。默认排除生成物、Git 忽略文件、凭据和链接。历史仅含文本指纹的记录会提示验证覆盖不足。当离线报告的工作区状态无法匹配时，ARC 保存报告并标明差异归属待核查。ARC 与 MCP 共享同一实际工作目录的执行约束。

AEC 迁移先冻结并导入旧上下文、REQ、规则及检查器原文，再替换明确可识别的管理块和官方脚本。旧文档作为待复核历史，旧“测试通过”不冒充实际执行；自定义规则与历史文件保留，无法识别的检查脚本报具体冲突。管理块在 ARC 模式下读写工程记录；旧检查入口检查实际记录、变更和证据，旧生成入口不再重新建包。ARC 自带此能力，不依赖单独安装 AEC。独立 AEC 用户仍保留原模式；迁移后的 Python checker 需要 Git 工作区。在绑定工程内直接运行 `python scripts/check_ai_context.py` 检查最新任务，或加 `--task <id>` 指定记录。在线模式按任务和工作区读取 ARC 中引用的观测日志。使用 `--arc-record` 检查本地记录时，可通过 `--arc-data-dir` 显式指定日志所在的 ARC 数据目录。曾迁移到上一版内置 checker 的工程可重新连接以升级已识别的脚本。

数据库从 v1 事务升级为 v2，只新增版本历史，不清空旧图、走读、问答或批注。“导出工程记录”包含所选工程的阅读数据、上下文、任务历史、冻结来源和引用日志；欢迎页或设置中的“恢复工程记录”可在空数据目录恢复，再显式绑定实际源码工作区。恢复不安装依赖、不恢复运行中的进程，也不等于还原可开发的完整源码仓库。冲突 ID 和不完整证据会拒绝导入，不能静默覆盖已有数据。SQLite 单库备份仍保留；跨机器完整恢复应使用工程记录导出。

## 启动与检查

需要 Node.js 22 或更新版本，以及已安装并登录的官方 Codex CLI。在仓库根目录执行：

```powershell
npm ci
npm start
```

已有依赖时直接 `npm start`，也可双击本目录或上级目录的 `启动Arc.cmd`。入口每次构建当前源码。Windows 启动脚本优先使用 `PATH` 中的 Git，找不到时尝试 Git for Windows 的标准安装路径，此设置只在本次启动进程树内生效。在 ARC 的“连接与设置”可填写受支持的官方 Codex CLI 可执行文件绝对路径。

本机启动脚本会在没有默认数据库、也没有显式 `ARC_DATA_DIR` 时，沿用已有的 `evidence/pmreq-acceptance-20261022/acceptance-data` 阅读成果；不会复制、迁移或覆盖数据库。`查看本次验收.cmd` 也已改为用当前源码打开这份数据，不依赖旧构建。清理时保留数据库、对应冻结快照、接入配置和测试仍读取的输入。

```powershell
npm run typecheck
npm run build
npm test
```

`npm test` 中两组原有测试依赖本机历史输入：`evidence/trade-readable-20261020/feature-result.json`、`evidence/readability-20261021/walk-result.json`、`evidence/multi-project-20261021/codex-feature-corrected.json`。这些未随 Git 发布，清理时仍保留它们；新克隆没有这些文件时，相关测试不能执行。新增阅读追问测试不依赖私有资料：`node --import tsx --test tests/reading-question.test.ts tests/reading-target.test.ts`。

实际界面验收使用 `npm run build` 后运行 `node --import tsx scripts/reading-journey-ui.mjs`。它打开真实 ARC 主进程源码，用明确标记的源码审阅导入结果作为阅读起点，后续问答调用已登录的真实 Codex，检查批注、来源、切换和恢复；不把导入结果算作 Agent 生成全图的证据。该检查会实际消耗当前 Codex 账户用量，使用上级 `.test-data/reading-journey` 独立数据目录，每次真实回答最多等待 5 分钟，失败时保留已取得结果以便继续核查，不属于默认单元测试。

`node scripts/project-onboarding-ui.mjs` 从界面打开完整当前仓库，验证真实全貌生成、独立关系复核、组件提问、批注、功能搜索和重启恢复。它也会消耗 Codex 用量，使用上级 `.test-data/project-onboarding`。`ARC_VERIFY_FRESH_OVERVIEW=1` 明确要求重新分析，并检查生成及复核总耗时低于 240 秒（本机旧基准 371 秒），记录实际耗时、原文体积及审核数量；这是验收门槛，不是所有工程的耗时保证。普通复跑复用新版已保存的真实结果，并输出 `newAnalysis: false`，不冒充新一轮模型验收。产品首轮执行与追问各最多等待 5 分钟；脚本会保留失败诊断。

`$env:ARC_VERIFY_NEW_PROJECT='1'; node scripts/project-onboarding-ui.mjs` 专门验收空数据下的首次打开，使用上级 `.test-data/first-analysis-current`，已有数据库时会拒绝复用。只在界面执行“打开并分析”，随后等待同一任务自动完成初审、关系补查和修订复核，再验证依据打开和重启恢复；记录从按下打开到最终保存的总耗时及各阶段耗时。如果真实初审没有发现关系疑点，脚本会明确指出补查分支未被覆盖，不用旧结果或模拟拒绝冒充通过。复跑前仅清理这份已确认可替代的测试数据，勿删除正常用户数据。

## 在一个位置连续问清楚

1. 点击“打开工程”，选择文件夹或输入路径，点“打开并分析”（输入路径后也可按 Enter）。新工程自动冻结源码、启动 Codex 并在 ARC 的“分析进度”显示过程，生成系统架构和功能目录；不用先配置 MCP 或切换到外部对话。“仅打开”只浏览文件；已有分析记录的工程恢复阅读，不重复派发任务。索引期间可在弹窗取消本次索引。
2. 在功能总览按名称或用途搜索，点击功能卡片即可展开；已有说明直接打开，尚未分析的功能在 ARC 内执行。文件组织也可搜索路径。
3. 点选节点、步骤、关系或文件，点击“就这里提问”，直接进入输入框。左侧保留当前图或文件；也可将提问范围切换为功能整体。
4. 点击“发送问题”或按 `Ctrl + Enter`（Enter 换行，输入法选词不会误发）。ARC 启动独立的官方 Codex 只读任务，自动带入对象说明、相关依据、用户批注和近期问答，无需重新描述背景。
5. 点击回答正文中的依据编号或下方源码卡，直接查看本次冻结文件、准确行号和哈希，再点“返回这条回答”回到原文。“查看最新回答”和“继续提问”始终可在右侧定位栏找到；回答到达不会打断旧内容。也可对任一回答点击“继续追问”。任务执行中切换对象或工程，回答仍归属原问题。
6. “这是纠错，同时保存为对象批注”会把输入保存为原对象的线索，后续分析仍须结合源码核实。失败或取消保留原问题和错误，可在原位置重试。
7. 文件或目录没有用途说明时，也可直接提问。问答、依据、对象关联和阅读位置保存在本机，切回或重启后可继续阅读。

默认沿用当前结果或所接续回答的冻结快照。“刷新并按最新代码回答”会明确建立新快照；旧图与旧解释保留原来源。每条回答可展开快照和问题版本。一次追问成功不代表整张工程图已更新，来源校验通过也不等于业务语义已经人工验收。

首次全貌分析先生成主要架构与已查证的功能目录，明确未覆盖范围；详细函数链、功能流程和异常在选中功能后再展开。Codex 直接执行的默认全貌任务使用当前模型和适中推理深度；不修改全局配置，自定义问题与深入任务沿用原设置。不会为了填满旧格式虚构关系，也不会把阶段性消息视作完成。

首轮传输采用 `overview-1`：只生成组件、功能、关系和短源码引用，ARC 核对逐字引用、冻结文件哈希和行号，再补入固定任务身份及原事实的引用结构。独立 Codex 任务依据同一快照逐条核对方向、通信方式、标签及摘要，绑定原草稿哈希；漏审、错绑、审核失败都不能发布。首屏不声明同步函数调用/返回，IPC 或跨进程交接不能显示为同步完成。复核仍是模型源码审阅，不等于运行验证或所有语义的证明；组件和功能职责也不能仅靠哈希校验认定正确。

发现关系有疑点时，ARC 自动补查调用点、装配位置与接收方，不把源码核对交给用户。补查使用 `overview-research-1`，新增依据必须匹配本轮真实 `arc_read_source` 回执、快照、哈希、连续行及逐字引用；不能抄旧说明冒充新读取。Agent 明确提出关系标签、类型、方向或说明的修订，再由独立任务仅复核修订关系，ARC 不按关键词硬改类型。每次分析最多一轮补查和一轮修订复核，全部阶段共用 5 分钟期限。确实仍缺依据时，结果保留已查源码和具体缺项；网络错误、超时或无有效回包显示“补查未完成”，不冒称源码不存在。

已有说明中的关系缺口可点“自动补查关系”：沿用该说明的冻结源码，当前图与问答保留，完成后通过“查看本次分析结果”打开新版本。重新启动也能恢复新旧版本及依据。原草稿、首次复核、补查原文和修订复核分别保存，旧记录不覆盖。

本机对同一 230 文件快照的真实 Codex 复验：首轮从 371 秒降至 112 秒（含独立复核约 21 秒），传输原文从约 58 KB 降至 11 KB。新结果包含 6 个主要组件、10 项功能；7 条候选关系中 6 条通过，1 条保留为待确认缺口。首轮按已查入口提供阅读起点，后续仍可深入未展开的功能；不同工程和服务响应速度会影响耗时。

后续对这条 MCP 提交关系的真实补查用时约 52 秒，包含 5 次源码读取与独立修订复核，恢复了第 7 条关系：桥接器在同一进程依赖结果校验与保存服务，`completed` 的具体返回发生在成果事务提交后，不能与 HTTP 200 或原始文件落盘混为一谈。可用 `$env:ARC_VERIFY_RESEARCH='1'; node scripts/project-onboarding-ui.mjs` 在已有本机真实验收数据上复验补查、源码打开及恢复；再设 `ARC_VERIFY_FRESH_RESEARCH='1'` 会重新调用真实 Codex，普通复跑明确标记复用结果。

2026-11-13 从空数据库重新打开当前完整仓库（237 文件）进行两轮真实首次分析，打开至保存分别为 124.8 秒、140.8 秒。最终构建这一轮包含冻结及打开约 1.0 秒、连接准备及初稿 114.8 秒、独立复核 24.5 秒、校验保存 0.5 秒；9 条关系均通过首审，没有触发补查。来源打开、精确引用及重启恢复另经界面检查通过，但“本次全新首轮自然发现疑点并自动补查、再复核”的实测覆盖仍未完成，不能将此前 52 秒补查与这次首次分析相加冒充一次完整耗时。验收入口保留该分支必须实际发生的断言，不因此宣称整体验收通过。

## Codex 与外部 MCP

Codex 直接执行使用已登录的官方 CLI（已适配 `0.163.0-alpha.10.2`、`0.167.0-alpha.4.1`）；设置里可检测连接并填写可执行文件路径。ARC 不收集密码或复制认证文件。子进程仅开放 `arc_list_files` / `arc_read_source`，限定到冻结源码，关闭外部 MCP、Shell 和文件修改工具，并隔离桌面宿主工具管道和会话身份。

Codex 检测记录保留 5 分钟，过期后发送任务会自动重新检测程序和登录状态，不会一直沿用旧版本的阻断结论。历史 MCP 待领取任务也不会挡住当前选择的 Codex 直接分析入口。

选择“外部 Agent · MCP 待领取”时，只登记问题，状态明确为“等待外部 Agent 领取”。在“连接与设置”展开可选的外部 Agent 接入并授权工程后，由外部对话领取；MCP 无法唤醒已经打开的对话。`arc_current_project` 返回待领取问题，`arc_begin_analysis` 可用 `question_id` 精确领取。直接执行和 MCP 共用同一冻结上下文与轻量校验。

普通追问采用 `reading-1`（回答、源码依据、未确认点和绑定），不要求重建 nodes/edges/claims。首轮精简格式经校验和复核后仍保存为原 `1.0` 合同；详细工程分析、DSH/MCP 和历史结果保持兼容，旧图不会被静默重写。近期上下文按对象及快照筛选；完整源码通过分页工具按需读取。

DSH、WorkBuddy 的既有 MCP 接入继续保留；本轮追问直接执行优先 Codex。原 DSH ACP/Web 与 WorkBuddy 后台协议代码保留，本轮未将其描述为新完成的真实联调。DSH 隔离依赖仍由 `provider-locks/dsh/` 管理，既有配置不因检测 Codex 被清空。

## 数据、边界与提交

日常数据默认在 `%APPDATA%\Arc`：`arc.sqlite`、`snapshots/`、`runs/`；`ARC_DATA_DIR` 可指定独立测试目录。备份数据库入口仍在设置中；完整恢复还需对应的冻结快照和运行文件。源码、批注和回答不会因新问答覆盖旧工程分析。退出时停止自有执行进程；重启遇未完成的直接任务会显示未知状态，不自动重发。

程序校验任务归属、快照、规范路径、整文件哈希和行号；事实是否足以支持结论仍需结合源码审阅。认证失败、连接故障、校验失败保留诊断，不能冒充完成。轻量追问和内置首次分析超过 5 分钟会请求停止，保留问题、公开进度和已取得的原文；首次分析的生成与复核共用同一期限，不重新计时。未支持的 CLI 版本会明确提示，不自动放宽工具权限。详细或自定义完整分析沿用原来的停止机制，不设总耗时上限。

本轮遵循 [项目规则](AGENTS.md)：每次完成修改与必要验证后提交并推送 GitHub；仅提交相关代码和文档，不提交凭据、用户数据、私有快照、历史证据或临时文件，不强推。按需打包仍可运行 `npm run package`，日常开发不额外生成分发包。
